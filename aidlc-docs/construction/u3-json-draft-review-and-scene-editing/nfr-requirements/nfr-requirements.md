# NFR Requirements: U3 JSON下書きレビューとシーン編集

## 性能と応答性

- U3 MVPは100シーン以下の台本を滑らかに扱えることを目標にする。
- Raw JSON入力中のバリデーションは短い待機時間後に実行し、入力操作を妨げない。
- 構造化シーン編集は即時に画面状態へ反映し、Raw JSON文字列の再生成も100シーン以下で実用的な速度を保つ。
- バリデーション中もエディタ入力をブロックしない。
- 大きい台本で検証が遅れる場合でも、最後に完了した検証結果と現在の編集中状態を混同しない表示にする。

## ファイル安全性と復旧性

- Apply前に`input/{videoId}.json.bak`を作成する。
- 既存の`.bak`がある場合は上書きしてよい。
- バックアップ作成に失敗した場合、`input/{videoId}.json`の上書きを開始しない。
- 正式JSONの保存に失敗した場合、下書き状態を保持し、再Applyや手動修正ができる状態を維持する。
- Discardはファイルを書き換えない。
- 正式な`input/{videoId}.json`にはGUI専用メタデータを書き込まない。

## 使いやすさ

- 既存台本の読み取り専用状態、編集中の下書き状態、無効状態、適用済み状態を画面上で明確に区別する。
- Applyボタンは無効な下書きでは押せない。
- Raw JSONが無効な場合、エラーを表示し、構造化ビューが最後の有効状態であることを示す。
- U3はElectronデスクトップGUIを前提とし、モバイル専用レイアウトは対象外とする。

## アクセシビリティ

- 基本対応として、通常のブラウザフォーカスで全操作をキーボード利用できることを目標にする。
- ボタン、タブ、入力欄は役割が分かるラベルを持つ。
- フォーカス状態は既存CSSまたは追加CSSで視認できるようにする。

## 保守性

- 下書き状態遷移、バリデーション、シーン編集ロジックはReactコンポーネントから分離する。
- Reactコンポーネントは表示とイベント接続を主責務にする。
- ファイル保存とバックアップ作成は専用アダプタに分離する。
- 既存の`VideoScript`型と`videoScriptSchema`を再利用し、別スキーマを増やさない。

## テスト容易性

- 下書き状態ロジックを単体テストする。
- 保存/Applyアダプタを注入可能なファイルアクセスでテストする。
- 主要コンポーネント操作をReact Testing Libraryでテストする。
- 100シーン程度の台本で、Raw JSON生成とバリデーションが破綻しないことを代表ケースで確認する。
